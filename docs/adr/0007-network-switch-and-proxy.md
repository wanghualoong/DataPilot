# ADR-0007 · 联网总闸与可配置代理

日期：2026-11-09　状态：已采纳

## 背景
用户问天气时，`web_fetch` 三次报 `kCFErrorDomainCFNetwork 310`，模型回答“沙箱默认无网络”。实测：
- 310 = HTTPS 代理连接失败。旧版把 `proxy-dku:3128` 写死为网页代理且默认开启，该代理对未列入白名单的站点 CONNECT 返回 403。
- 系统实际用 PAC：未列名站点直连，直连 wttr.in 返回 200。
- 「联网」开关只管沙箱内 python/bash，`web_fetch` 在 App 进程中运行、不受开关控制；系统提示也没说明这一点。

## 决策
1. 「联网」开关是所有联网工具的唯一闸门，默认关闭；关闭时调用联网工具会请求用户开启，而不是静默失败。
2. 代理三种模式：跟随系统（默认，含 PAC）/ 直连 / 自定义；Provider 可跟随全局或单独设置。代码中不写死任何代理。
3. 代理层错误自动直连重试一次，错误信息可读化。
4. 系统提示写明联网由开关决定、失败要报告具体错误。

## 理由
与 Codex 一致（网络默认关、按需批准）；跟随系统代理是浏览器的做法，最不容易“在别的网络里用不了”；开源后不带任何机构特定配置。
