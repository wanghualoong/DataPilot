## 2. cablate 分析中提炼的设计要点 → DataPilot 做法

### 2.1 记忆子系统分工
分析里把记忆拆成几个**触发时机不同、互不阻塞**的子系统：
| 子系统 | 触发 | DataPilot 对应 |
|---|---|---|
| 会话笔记（session memory） | 上下文 token 达到门槛 | L1 `notes.md` |
| 记忆抽取（extract memories） | 每轮结束，后台执行 | L3 候选记忆抽取 |
| 记忆整合（auto dream） | 时间 + 会话数双门槛 | 每日整合 |
| 上下文压缩（compact） | 接近窗口上限 | 自动压缩 |

### 2.2 会话笔记（L1）
- **启动门槛**：上下文累计约 1 万 token 才开始写（短对话不需要）。
- **更新门槛**：此后每增长约 5 千 token、并且期间有工具调用（或本轮没有工具调用）才更新一次。
- **固定章节模板**，只更新章节内容、不改标题。DataPilot 的模板改为数据分析专用：
  `目标 / 当前状态 / 数据集与表 / 口径与定义 / 关键发现 / 派生表与产物 / 错误与纠正 / 待办`。
- **大小控制**：单章节过长（约 2k token）或总量过大（约 12k token）时，要求模型压缩该章节。
- 压缩时**优先用会话笔记代替整段摘要**，可以省掉一次 LLM 调用。

### 2.3 记忆抽取（L3 候选）
- **增量游标**：只处理上次抽取之后的新消息，不重复扫描整段对话。
- **与主 Agent 互斥**：如果主 Agent 本轮已经调用 `memory_write`，后台抽取就跳过本轮。
- **最小权限**：抽取任务只能读对话、只能写记忆库，不能调用数据或文件工具。
- **失败静默**：出错只记日志，游标不前进，下次自动重试，不打扰用户。
- **两步完成**：第一步并行读取已有记忆，第二步并行写入或更新，减少来回次数。

### 2.4 记忆整合（每日 dream）
- **门槛按成本从低到高检查**：距上次整合 ≥ 24 小时 → 新增会话 ≥ 5 个 → 获取锁（防止多窗口同时整合）。
- **四个阶段**：了解现有记忆 → 收集新信号（事件日志、情景摘要）→ 合并（相对日期改为绝对日期，删除被推翻的事实）→ 修剪索引。
- 索引保持在 **200 行 / 25KB** 以内；超出时截断并给出警告，不拒绝加载。
- 失败时回滚锁的时间戳，保证下次门槛仍然有效。

### 2.5 记忆可信度与时效
- 记忆是“某个时间点的观察”，不是实时状态。注入时附上记忆的日期；超过一定天数的记忆加上“可能已过期，使用前先核实”的提示。
- 可信度从高到低：当前数据（实时查询结果）> 新记忆 > 旧记忆。数据口径一旦与实际数据冲突，以查询结果为准，并提示用户更新记忆。
- **只存不可推导的信息**：表结构、行数这些可以随时查到的东西不进长期记忆；口径、偏好、纠正才进。

### 2.6 上下文压缩
- **触发点留足余量**：不要等到窗口快满才压缩，要给摘要输出和下一轮回复预留空间。DataPilot 默认在 80% 触发（本地模型窗口小）。
- **熔断**：连续 3 次压缩失败就停止自动压缩，提示用户手动处理，避免死循环。
- **防递归**：压缩调用本身、会话笔记更新调用不触发压缩检查。
- **保留近期原文**：从最后一条消息往前保留约 1 万～4 万 token（按窗口比例缩放）的原始消息；工具调用和结果必须成对保留。
- **摘要提示词**：先在 `<analysis>` 里打草稿、再输出 `<summary>`，草稿丢弃；开头明确要求“不要调用任何工具，只输出文本”。
- **应急路径**：请求返回“上下文过长”时，立刻强制压缩后重试一次。

### 2.7 工具编排
- 按顺序把工具调用**分批**：连续的只读、可并发工具合成一批并行执行，遇到写操作就单独串行。
- 并发上限 10。
- 工具错误以错误结果回传模型（让模型自己纠正），而不是中断循环。
- 多层检查顺序：参数 schema 校验 → 工具自定义校验 → 权限决策 → 执行 → 结果截断。
- 权限规则优先级：deny → allow → 自动允许 → ask。

### 2.8 Skills
- 目录只放名称和描述，占上下文约 **1%～2%**；单条描述截断到约 250 字符。
- 正文在调用 `skill` 工具时才加载（渐进披露）。

### 2.9 上下文注入（system reminder）的教训
- 分析记录了一类问题：系统自动往每条用户消息里注入的提醒越来越多，最终占掉大量上下文，甚至覆盖了用户自己的指令。
- DataPilot 的做法：
  - 注入内容（记忆、内核状态、数据集口径）统一走一个 `ContextAssembler`，**有总预算**（约上下文的 10%）。
  - 只在内容**变化时**注入，不在每轮重复。
  - 注入块在 UI 中可见（可折叠），用户能看到模型到底收到了什么。

### 2.10 Prompt 缓存稳定性
- 系统提示词按“稳定部分在前、动态部分在后”排列；工具定义顺序固定。
- 对本地 vLLM（prefix caching）同样有效：前缀不变，首 token 延迟显著降低。
