# 04 · 记忆系统

实现（现为 Rust）：`datapilot-core/src/memory.rs`（主题记忆文件）、`recall.rs`（召回）、`extract.rs`（抽取）、`dream.rs`（整合）、`notes.rs`（会话笔记）、`index.rs`（Q-SQL / 数据集索引 index.sqlite）。下文前半部分是 Swift 时期的 SQLite 记忆库设计（已删除，仅作历史记录）；当前设计以「第三轮改造」及之后章节为准。

## 回答三个问题
**会不会记得用户历史操作？** 会。三种粒度：
1. `events`：每次工具调用（导入/查询/建图/看板/导出/纠正/👍）一条，含会话、数据集指纹、参数摘要、结果、耗时。
2. `episodes`：每个会话的情景摘要（标题 + 会话笔记或最近问答），每轮后台更新。
3. `qsql_pairs`：`sql_query` 带 `question` 且有结果时自动积累；用户点 👍 标记为 verified，检索时优先。

再加上**数据集指纹**（规范化列名+类型的哈希）：同指纹或列集合 Jaccard ≥ 0.7 视为同类报表，自动继承口径规则，并注入“该数据集的历史分析”。

**短期与长期如何结合？**
| 层 | 内容 | 写入时机 | 读取时机 |
|---|---|---|---|
| L0 工作记忆 | 当前上下文消息 | 实时 | 始终 |
| L1 会话笔记 `notes.md` | 固定 8 节模板（目标/状态/数据集/口径/发现/产物/错误） | 上下文 ≥1 万 token 后，每增长 5 千 token 且（≥3 次工具调用或本轮无工具）由快速模型重写；压缩前强制刷新 | 每轮注入（预算内）；压缩摘要以它为准 |
| L2 情景/事件/Q-SQL | 见上 | 每轮后台 | 按当前问题关键词检索 |
| L3 语义/偏好 | 用户画像、习惯、数据集口径/规则 | 显式、纠正、后台抽取、行为统计 | 每轮注入 active 项（按置信度截断） |
| L4 程序记忆 | Skills | 用户确认保存 | 目录常驻，正文按需 |

每轮注入顺序：日期 → 用户画像/习惯 → 数据集口径 → 数据集历史 → 工作区状态 → 会话笔记 → 相关历史会话 → 已验证 Q-SQL。总预算 ≈ 窗口 10%，**内容不变不重复注入**。

**如何学习分析习惯？** 信号 → 候选 → 证据累积 → 生效：
| 来源 | 状态 | 示例 |
|---|---|---|
| 显式 `explicit`（“记住…”） | 立即 active | 金额单位用万元 |
| 纠正 `correction` | 立即 active，最高优先级 | 收入要剔除退款 |
| 后台抽取 `extracted` | pending，证据 ≥3 或用户确认后 active | 总是看同比 |
| 行为统计 `behavior`（代码计数，不耗 LLM） | 达阈值生成 habit | 图表类型切换、常用维度、chart_type |
写入时与同 scope 的近似条目（字符二元组重叠 ≥0.6）合并并累加证据。

## 后台子系统
| 子系统 | 触发 | 要点 |
|---|---|---|
| 会话笔记 | token 门槛 | 只改章节内容；超 12k token 要求压缩 |
| 记忆抽取 | 每轮结束 | 增量游标（失败不前进）；主 Agent 本轮已 `memory_write` 则跳过；只读对话、只写记忆库；失败静默 |
| 每日整合 | 距上次 ≥24h 且新会话 ≥5，加锁 | 确定性衰减（pending 30 天、行为类 180 天未用 → 归档）+ 快速模型合并重复/冲突/相对日期；失败回滚时间戳 |

## 可信度与时效
- 注入时超过 60 天的记忆附“可能过期，使用前核实”。
- 当前查询结果 > 新记忆 > 旧记忆；口径与数据冲突时以数据为准并提示更新。
- 只存不可推导信息，不存原始数据值。设置中可关闭长期记忆。

## 检索（Retriever）
与 Codex / Claude Code 一致，**只用关键词检索，不接 Embedding / Rerank 模型**（见 ADR-0006）：
- 记忆、情景摘要、Q-SQL：SQLite FTS5 trigram BM25（中文可用）→ top-k；无命中时退化为中文二元组重叠（≥0.5）。
- 文件内容：Agent 按需调用 `grep`（正则搜索内容）/ `glob`（按文件名找文件），就像 Claude Code 的 Grep / Glob。
- 记忆本身很少（通常几十到几百条），且画像/习惯/数据集口径是按置信度**全量注入**的，检索只用于情景记忆与 Q-SQL 的补充召回。

## UI
检查器“记忆”页：已生效 / 待确认 / 已归档；右键确认、编辑、归档、删除；手动添加偏好；底部显示行为统计。工具栏 👁 可查看每轮注入了什么。

## 显式调用 skill（/skill名）
通过 `/skill名` 调用时，核心（`agent.rs`）在本轮把 SKILL.md 全文作为 meta 消息注入上下文（`AgentSession.skillMessage`），不再依赖模型自己去调用 `skill` 工具；界面会显示“📘 已加载 skill”。模型自己判断需要时，仍按 skill 目录调用 `skill` 工具加载。

## 条目格式与评估（2026-11-12）
- 项目记忆正文：`规则一句话（尽量原样引用用户原话「…」）` + `**依据：**`（用户原话 / 验证过的 SQL 或结果）+ `**状态：** confirmed|pending` + `**How to apply:**`。旧条目的 `**Why:**` 继续有效，整合时并入依据。
- 抽取器类型：rule / definition / trap（容易做错的做法，存为 feedback）/ preference / habit；同一主题给出 `file` 时覆盖已有文件，不新建。
- 评估：`scripts/run_memory_eval.py --memory on|off [--prompts 目录]`。每题新会话、答完给参考答案和口径；预置 10 条无关记忆和 1 条过期冲突口径。除正确率外输出 hygiene：`topic:*`（同主题文件数，理想 1）和 `stale`（标题/首行仍主张旧口径的文件，理想 0）。
- 注意：`--memory off` 并非完全无记忆——模型会用 `catalog_update` 把口径登记进项目语义层，后续会话能读到。

## 做梦整合 B3（Rust 核心，2026-11-12）
实现在 `datapilot-core/src/dream.rs`，提示词 `Resources/prompts/memory_consolidate.md`。

| 项 | 做法 |
|---|---|
| 触发 | Due：回合结束后检查，距上次 ≥24 小时且有 ≥5 个其他会话（最多 10 分钟检查一次）；Idle：server 线程每 15 分钟扫描空闲会话，距上次 ≥6 小时且记忆有变；Manual：聊天输入 `/dream` 或 RPC `memory/dream`，跳过门槛 |
| 输入 | 全部主题文件 + 最近 ≤10 个会话的用户/助手摘录（≤12k 字，密钥抹掉）+ 依据中 SQL 的只读重跑结果（内核 `sql` op，`limit 3`，每次 ≤10 条） |
| 输出 | `{"update":[…],"delete":[…],"core":[…]}`：合并重复、相对日期改绝对、按重跑结果修正或标 pending、删除被推翻的条目；每次新增主题 ≤3 个 |
| core 块 | `MEMORY.md` 顶部 `<!-- core:start -->…<!-- core:end -->`，≤8 行，放最常用的口径，随系统提示加载 |
| 安全 | 锁文件；整合前快照，失败恢复；非手动触发时要删除过半主题则放弃；上一版保留在 `<dir>.prev`，`/dream undo` 恢复 |
| 记录 | 每次运行（含跳过原因）追加到 `.dreams.jsonl`；完成后发 notice，结尾提示“可用 /dream undo 撤销” |

## 用户层召回 B4（Rust 核心，2026-11-12）
召回候选 = 项目记忆 `.datapilot/memory/` + 用户记忆 `AppSupport/memory/`，合并后按修改时间取最新 200 个。用户层文件在清单和注入块里写作 `[mem:user:文件名]`，引用计数写回各自目录的 `.usage.json`。没有打开项目时也会召回用户偏好。两层冲突时以项目记忆为准（写在注入块说明和 `memory_recall.md` 里）。

## 隔离语义层的记忆评估（2026-11-12）
`run_memory_eval.py --isolate-catalog`：每个会话开始前清空 `catalog.json` 的 metrics / synonyms，口径只能靠记忆系统带到后续会话；`intro_questions`（s1、s3：口径第一次出现的题）不计入「可学」分。Rust 核心 + DeepSeek：

| 条件 | 总分 | 可学题 | 记忆卫生 |
|---|---|---|---|
| 记忆关 | 0/8 | 0/6 | – |
| 记忆开 | 5/8 | 5/6 | GMV 同主题 2 个文件，活跃客户 1 个；无过期口径残留（75 天前的旧 GMV 口径已不再被主张） |

记忆开的唯一可学失分是 s2（第一次复用 GMV 口径）。s1 在记忆开时超时（模型流 917 s 无响应，属网关问题，不是答错）。

复跑（修了流式卡住之后，`iso2`）：记忆开 **6/8，可学题 6/6**，`stale` 为空。第一次 s2 失分的原因是 s1 超时，没有拿到反馈，旧的“含退款”记忆没被改写；这次 s1 正常结束，模型直接把 `gmv-旧口径.md` 改写成新口径（没有另建重复文件），后面的 GMV 题全对。`topic:GMV = 2` 是指标误报：另一个文件是「目标完成率口径」，描述里提到了 GMV。
